# COMMENT 逻辑关系

MySQL 管理器使用表与字段 COMMENT 中的显式声明呈现逻辑关联。它读取当前账号可见的结构元数据，不扫描业务数据、不创建物理外键、不自动修改注释。

## 声明语法

### 单字段引用

在来源字段 COMMENT 中写入：

```sql
COMMENT '创建记录的用户 @ref(users.id)'
```

同字段可以包含多个声明，重复引用去重。`@ref(schema.table.column)` 可以保留跨库声明，但当前只读取所选库；跨库目标不校验、不生成 JOIN。标识符支持字母、数字、下划线与 `$`，不支持包含空格或点号的单个标识符。

### 多字段关联

在来源表 COMMENT 中写入：

```sql
COMMENT '业务记录 @relation((tenant_id,user_id)->users(tenant_id,id))'
```

两端至少两个字段、数量相同、各端没有重复，严格按顺序配对。只接受当前库的 ASCII 普通标识符：字母或下划线开头，后续为字母、数字或下划线。可写多条声明；引号、表达式、库名前缀或残缺语法不被部分解释。

有效声明生成包含全部 `ON` / `AND` 条件的查询草稿。任意字段不存在或不可见时，整条关系禁用 JOIN；类型不同给出提示，不表示业务关系已获认证。

### 表级业务映射

在来源表 COMMENT 中写入：

```sql
COMMENT '相关审计记录由应用维护 @mapping(audit_events)'
```

目标只接受当前库的 ASCII 普通表名，可声明多个并去重。映射没有字段配对、关系基数或目标行存在保证；连接表头，以独立线型和「业务映射」文字区分，始终禁止生成 JOIN。

仅中文说明和同名字段不会自动生成关联。COMMENT 是维护源，无需另外维护关系配置文件。

## 浏览与查询

- 数据库导航中的「逻辑关系」读取元数据，「刷新结构」重新发现声明。
- 卡片显示表、字段和中文注释；完整原始 COMMENT 在详情中展开。
- 搜索支持技术名称和业务说明，可按关系类型及显式关联形成的连通组筛选。
- 自动布局按依赖分层，循环引用归为同层；密集组合关系显示一条主线，选择后展开字段分支。
- 拖动和滚动平移，触控板捏合或 Ctrl/Cmd+滚轮缩放，按钮提供适应全图、原始比例与定位所选。画布聚焦后可用方向键平移、Home 适应全图。
- 有效字段关联仅生成带 `LIMIT 100` 的 `LEFT JOIN` 草稿，不自动执行。业务映射与缺失目标均禁用 JOIN。

布局和路径为确定性启发式，优先避开卡片并减少重复通道，不保证任意稠密图零交叉。画布最多展示筛选后的 100 条关系；声明列表保留全部关系。

## 分享交互式 HTML

导出当前组、类型和搜索范围，包含相关表的全部字段名称、类型、键、COMMENT、关系详情与有效字段关系的只读 SQL 草稿。查看器独立于宿主，支持搜索、筛选、平移缩放、完整字段说明；无 JavaScript 时保留静态说明。

产物为单个 HTML，内嵌 CSS、JavaScript 和快照，禁止外部资源及网络连接。注释按文本显示，不执行其中的 HTML。每次最多 100 条声明、最大 2 MiB；超过时拒绝导出，需要用户缩小范围。离线过滤保持原布局位置。

导出不包含业务行、连接配置或凭据，但结构名、注释和 SQL 草稿属于文件内容，分享前应按这些内容确定接收范围。快照不会自动更新；MySQL 之外的数据库需要单独适配元数据采集。

## 实现与验证边界

解析、元数据校验和 SQL 生成在 `relations.ts`，布局与走线分别由 `relation-layout.ts`、`relation-routing.ts` 负责。在线和导出通过 `relation-scene.ts` 共用几何计算。相机输入按帧合并，布局和路径缓存不随相机移动重算。

测试覆盖语法与去重、完整多字段条件、目标缺失、类型提示、映射禁 JOIN、确定性布局、路径避障、相机数学与帧调度，以及导出白名单、注入转义、确定性和体积限制。桌面与本机 HTTP 预览已验证主要交互；本地文件双击、断网、禁用 JavaScript、物理捏合、多平台与窄窗口尚未完整实测。不承诺固定帧率、关系基数或数据一致性。
