# MySQL 管理器插件

MySSH的MySQL数据库管理工具，提供类似Navicat的功能。

## 功能特性

- 📊 **连接管理**: 支持保存多个MySQL连接配置
- 🗄️ **数据库浏览**: 查看所有数据库和表结构
- 📝 **SQL编辑器**: 支持语法高亮和自动补全
- 🔄 **查询执行**: 支持执行任意SQL查询
- 📋 **结果展示**: 表格形式展示查询结果，支持排序和分页
- 📤 **数据导出**: 支持导出CSV格式

## 架构说明

由于浏览器安全限制，插件无法直接连接MySQL服务器。采用WebSocket代理架构：

```
MySSH插件 (浏览器) <--WebSocket--> 代理服务 <--TCP--> MySQL服务器
```

## 安装步骤

### 1. 安装并启用插件

MySQL Manager `1.1.0` 声明了 MySSH `1.3.0+` 的官方 Companion Runtime。正常使用时，
插件首次连接数据库会由 MySSH 自动校验并启动内置代理，自动分配本机端口和临时 token，
不需要用户手动运行 Node 服务。

### 2. 手动代理回退（开发 / 远程部署）

```bash
cd src/mysql-manager/proxy
npm install
npm start
```

代理服务默认只监听本机 `ws://127.0.0.1:3000`。在连接表单中填写「代理地址」后，插件会优先使用该地址；远程代理请使用
`wss://` 并在服务端启用访问 token。

### 3. 安装插件

在MySSH设置中添加插件市场地址：
```
https://chengyunlai.github.io/my-ssh-plug/registry.json
```

然后在插件市场中安装 "MySQL 管理器" 插件。

### 4. 配置代理地址（可选）

如果代理服务运行在其他地址，在连接表单中填写「代理地址」，例如
`wss://db-proxy.example.com:3000?token=change-me`。显式填写的地址始终优先；新建连接留空时使用
MySSH Companion Runtime，未接入宿主 runtime 的旧插件才回退到本机默认地址。

## 使用方法

1. **创建连接**: 点击"新建连接"，填写MySQL服务器信息
2. **连接服务器**: 点击"连接"按钮
3. **选择数据库**: 在左侧树形菜单中点击数据库名称
4. **执行查询**: 在SQL编辑器中输入查询语句，按Ctrl+Enter执行
5. **查看结果**: 查询结果显示在下方表格中

## 配置选项

### 代理服务环境变量

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `MYSSH_RUNTIME_HOST` | `127.0.0.1` | MySSH Companion Runtime 注入的监听地址，不建议手动覆盖 |
| `MYSSH_RUNTIME_PORT` | 0 | MySSH Companion Runtime 使用动态端口 |
| `HOST` | `127.0.0.1` | 手动代理监听地址；非回环地址需要同时配置 token 与明确来源 |
| `PORT` | 3000 | 手动代理 WebSocket 服务端口 |
| `ALLOWED_ORIGINS` | `null,myssh-plugin://mysql-manager` | 精确匹配的来源列表（逗号分隔），禁止 `*` |
| `ACCESS_TOKEN` | 无 | 非回环监听必填；客户端在代理 URL 的 `token` 查询参数中携带 |

### 安全建议

1. **限制来源**: 远程部署必须设置 `ALLOWED_ORIGINS` 为完整来源（例如 `https://app.example.com`），服务端会精确匹配
2. **使用HTTPS**: 远程部署建议通过HTTPS/WSS协议传输，并设置随机 `ACCESS_TOKEN`
3. **密码安全**: 连接密码仅存储在本地浏览器，不会上传到任何服务器

## 故障排除

### 连接失败

- 检查代理服务是否运行: `curl http://127.0.0.1:3000`
- 检查MySQL服务器是否可达
- 检查防火墙设置

### 查询无响应

- 检查代理服务日志
- 确认MySQL用户有执行权限
- 检查查询语法是否正确

## 1.2.0 的终端适配

MySSH 1.5.0+ 可通过同一市场安装终端入口。TUI 提供加密连接配置、库表/结构/索引/建表 SQL、
分页与当前结果排序、参数化行新增/修改/删除、SQL/编辑器/历史、CSV 导出。SQL 编辑高亮与补全由配置的本地编辑器提供。

终端 Core 直接连接用户输入的 MySQL 主机，不要求代理或额外 Node 服务；可启用严格 TLS 证书验证。
TUI 与桌面连接存储独立，不自动迁移旧 localStorage。当前结果受行数/列数/字节/时间上限约束，
CSV 仅导出当前结果，并将危险公式前缀转为文字；查看完整数据可自行分页或使用明确的 SQL 查询。

## 1.3.0：Kubernetes 来源

配合带 Kubernetes 能力的 MySSH 开发版：先到宿主独立「Kubernetes」面板导入 kubeconfig，并按有权限的命名空间发现服务；再新建连接，选择 Kubernetes 服务，填写 MySQL 账号。MySQL 与未识别的服务可以手动选取；Redis/PostgreSQL 需使用对应客户端。

连接时由宿主建立独立回环通道，本插件将实际临时端口交给本机官方 Companion Runtime。Kubernetes 连接的代理地址默认留空；本地开发可填写回环地址的手动代理，拒绝远程代理，密码只在本次运行内存保留，不写入 localStorage。断开/连接失败/面板卸载时关闭通道；Pod 退出则提示重新连接，不重试 SQL。重启后需重新导入并发现同一配置文件；旧宿主仍支持原有手动连接。

本次未改变手动地址连接的既有凭据存储。通道与 kubeconfig 凭据均由宿主拥有，插件不直接启动 kubectl。

### 复杂字段显示

表内容和 SQL 结果将 JSON 显示为可展开的完整文本；二进制字段中的有效 UTF-8 文本直接显示，其他字节显示为十六进制。长内容点击展开后可选中复制。复杂字段暂不支持双击编辑，避免隐式转换后写回；CSV 导出复用相同转换规则。

侧栏右侧分隔线支持拖动调整宽度并记住设置；双击恢复默认宽度，聚焦分隔线后可用左右方向键调整。悬停表名或数据库名可查看完整名称。

JSON 单元格提供树形/原文切换、字段类型着色和复制完整 JSON；对象与数组可逐层折叠，单层超过 100 项时按需加载，正文区域独立滚动。

打开表默认进入内容视图。JSON 在单元格内只展示字段数摘要；点击查看打开只读详情面板，支持按键/值搜索、树形/原文、复制和全屏，Esc 关闭并返回触发按钮。

## 注释声明的逻辑关系图

连接数据库后，点击所选数据库下面的「逻辑关系」。插件只读查询当前库的 `information_schema.COLUMNS`，读取最新字段注释；点击「刷新结构」可重新发现。

声明格式：`@ref(users.id)` 或 `@ref(app.users.id)`。标识符支持字母、数字、下划线和 `$`；同字段可包含多个声明，重复声明去重。当前版本不支持带空格/点号的引用标识符，也不支持复合字段组。

图中只展示有关联的表及引用字段/主键。连线表示源字段引用目标字段，不推断一对一/一对多；下方列表、图中连线均可选择，详情展示原注释与结构校验。点击表名打开内容；「打开 JOIN 查询」将生成带 `LIMIT 100` 的 `LEFT JOIN`，由用户审阅后执行，不自动运行。

目标不存在或账号不可见时显示未校验，禁用 JOIN；跨库目标保留声明但不读取其他库。类型不同给出提示。注释格式错误单独列出；无声明、加载、查询失败、无筛选结果有独立状态。SQL 标识符转义、元数据查询使用十六进制编码的库名，注释仅作为数据解析。

缩放、适应画布和原生滚动用于浏览；关系视图临时隐藏插件内部侧栏，切回表/查询后恢复。图最多展示筛选后的前 100 条，声明列表仍保留全部关系。此功能没有新依赖，不创建外键、不执行 DDL、不扫描业务数据、不分析 SQL 历史或自动猜测关联。

关系图同时读取表 COMMENT：表名下显示表说明，字段名下显示不含 `@ref` 的业务说明。卡片长注释单行省略，悬停查看全文；关系详情分别显示引用端和目标端的完整表/字段注释，可展开原始注释。工具栏可隐藏卡片注释以缩小布局；搜索支持技术名称与两端业务注释。显示开关会同步重算节点高度和连线锚点。

关系画布支持空白处或卡片非按钮区域左键拖动、中键拖动、双指滚动平移和触控板双指捏合缩放（Chromium ctrl+wheel）；也支持 Ctrl/Cmd+滚轮。缩放围绕鼠标/手势位置，范围 20%–300%。聚焦画布后方向键平移、Home 适应全图，空格按住可从控件上开始拖动。

### 表 COMMENT 中的组合关系

单字段保持 `@ref(table.column)`；组合关系从表 COMMENT 读取，例如 `@relation((thread_id,owner_id)->conversations(id,user_id))`。只支持当前库的 ASCII 普通标识符，两端至少两列、数量相同且各自无重复，按顺序配对。同一声明在列表中是一项；其所有字段和连线一起选中，JOIN 草稿使用 AND 连接全部配对条件，不自动执行。格式错误显示诊断，任一字段不存在或不可见时禁用生成；类型差异提示但不声称业务一致性或关系基数。

卡片和详情中的中文说明与机器声明分开，原始表/字段 COMMENT 可展开查看。仅中文跨模块映射不生成关系，同名字段不自动连线。不展示基于 COLUMN_KEY 推测的组合唯一性。SQL COMMENT 是维护源，无额外关系 JSON 或必需手动配置。

关系画布自动按引用方向分层，同层顺序通过重心排序减少交叉，再对齐关联卡片并避免重叠。循环引用归入同层；直接叶子表靠近来源表。布局为确定性启发式，不保证所有关系图都没有交叉。

### 画布优先的关联浏览

关系图根据显式声明的连通分量形成独立关联组，不根据表名前缀、中文说明或同名字段推断分组。总览中各组独立布局与走线，再做两列紧凑排布；组导航可单独查看一组，搜索在当前组内过滤。画布默认使用工作区剩余高度，右侧「关系详情」按需展开；点击连线选中整条关系，其他线淡出，详情列出全部配对字段。「定位所选」聚焦两端表，「100%」恢复原始比例，「适应画布」查看当前范围，Escape 收起详情并恢复按钮焦点。开关详情只调整视野中心，保留缩放比例。紧凑屏幕的详情使用覆盖面板，可收起恢复画布。

### 业务映射 @mapping（协议 v1.1）

表 COMMENT 可声明 `@mapping(target_table)`，只接受当前库的 ASCII 普通表名，可多次声明并按来源/目标去重。它是应用或 SDK 的表级定位联系：没有字段配对、基数或目标行存在保证；不能根据同名 scope_hash 推断映射。目标缺失仍显示并提示。

业务映射默认可见，采用紫色点线并标「业务映射」，连接表头而非字段。工具栏可筛选全部类型、字段关联或业务映射；显式映射参与分组，组文案标明「含业务映射，不代表可 JOIN」。摘要隐藏完整合法机器声明，详情保留中文定位规则与原始 COMMENT。「打开 JOIN 查询」「复制 SQL」对映射禁用，`relationJoinSql` 也直接拒绝 mapping 类型；原字段 ref/relation 的全部 AND 条件与草稿行为不变。

### 密集连线的阅读方式

组合声明在总览中绘制一条主线并标注字段数量；选中后展开两端字段分支，同时高亮全部配对字段。跨列、回向及自引用路径在卡片之间搜索正交通道，代价考虑距离、转弯与已占用通道；短距关系保留曲线。交叉处有背景描边，选中线最后绘制以便追踪；字段计数与业务映射标签放在主线的水平通道。路由和布局缓存不随拖动、缩放重复计算。此启发式减少绕行和重叠，不保证任意复杂图零交叉。

### 结构页中文注释

结构页从指定库的 `information_schema.COLUMNS` 与 `TABLES` 读取元数据，顶部显示表说明，字段名旁显示可换行的注释列。未填写时明确标示；合法关联声明从中文摘要中移除，可展开「原始 COMMENT」查看。查询失败显示错误，切表时旧结构请求不会覆盖新结果；此功能只读，不修改 COMMENT。
